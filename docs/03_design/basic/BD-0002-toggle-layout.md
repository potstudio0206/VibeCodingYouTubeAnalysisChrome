### 2.2 行の高さを View の定数とする理由
- 行の高さは「1行を何ピクセルで描くか」という描画の寸法で、表示の状態（どの表示か、どの範囲か）から何かを計算するものではない。したがって View の定数（`LABEL_W`・`MARK_H`・`AXIS_H`・`GAP` と同じ並び）に置く。ViewModel には置かない。
- 変更後は `S.mode` が高さに関わらなくなる。`S.mode` は「どちらの描き方をするか」の分岐（352行の `if (S.mode === 'heat')`）にだけ使われる（現行どおり）。

### 2.3 既知の逸脱（本件で増やさない）
- BD-0001 の D-2（content.js がパネルの状態 `S` を持つ）はそのまま。本件は描画の寸法だけを変えるので、逸脱を増やしも減らしもしない。

### 2.4 検討して採らなかった案
| 案 | 内容 | 採らなかった理由 |
|---|---|---|
| 案2 | 領域を 189px にそろえ、ヒートマップは 18px の行のまま下に余白を足す | グラフの下に約80px の空白ができ、不自然に見える |
| 案3 | 両表示を 109px にそろえ、折れ線の行を 18px にする | 折れ線の起伏が読みにくくなる。折れ線は「山の形を細かく見る」ための表示で、その目的に反する |
| 案4 | 中間の行の高さ（例：28px）にそろえる | 両方の見た目が変わり、見やすさの好みの確認が二重になる |
| canvas の高さを CSS で固定し、描画を拡大縮小する | `canvas.style.height` を固定値にして中身を伸縮 | 文字（ラベル・時刻）が縦に伸び縮みして読みにくくなる。行数が変わったときの扱いも複雑になる |
| ボタン類をグラフの上に移す | 並べ替えボタンをグラフの前に置く | REQ 3.2 で範囲外。画面の構成が大きく変わる（C-3） |

## 3. 処理の流れ
### 3.1 変更前と変更後（drawChart の高さの決め方）
```
変更前（content.js 331〜332行）
  rh = S.mode === 'heat' ? 18 : 38
  H  = MARK_H + R.length × (rh + GAP) + AXIS_H        … 表示によって 109px / 189px（4行）

変更後
  定数（324行の並び）に ROW_H = 38 を足す
  rh = ROW_H                                            … 表示に依らない
  H  = MARK_H + R.length × (ROW_H + GAP) + AXIS_H      … どちらの表示でも 189px（4行）
```
- 349行以降の `rh` を使う箇所（行の位置 `y`、ラベルの縦位置 `y + rh / 2`、背景 `fillRect(LABEL_W, y, PW, rh)`、ヒートマップの塗り `fillRect(x, y, 1, rh)`、折れ線の縦の位置 `y + rh - 2 - …*(rh - 4)`）は、式を変えずにそのまま使う。結果として：
  - 折れ線：`rh` が 38 のままなので、描かれる画素は現行と同じ（見た目は全く同じ）。
  - ヒートマップ：各行が 38px の太さで塗られる。ラベルは行の縦の中央（y + 19）に来る。
- 変数 `rh` を残して `const rh = ROW_H;` とするか、`rh` を `ROW_H` に置き換えるかは詳細設計で決める（どちらでも結果は同じ）。

### 3.2 切り替え・幅の変更の流れ（現行どおり。テストの待ち方の根拠）
```
[「折れ線」/「ヒートマップ」を押す] setMode(m)
  └─ S.mode = m、hlx-on の付け替え → drawChart()（同期）
       └─ canvas.style.height = H + 'px'（H は表示に依らない → 値は前と同じ）
[⇔ を押す]
  └─ S.wide 反転、.hlx-wide の付け替え（幅 400px ⇔ 760px）→ setTimeout(drawChart, 220)
[表示範囲を変える] S.range = 値 → drawChart()（同期）
[ウィンドウの大きさを変える] resize → drawChart()
```
- 切り替えは同期処理なので、テストはクリックの後に描画の完了を待つ特別な仕組みは要らない見込み。ただし念のため、TS では「canvas の高さの値が2回続けて同じになるまで待つ」などの待ち方を決める（REQ 8章(6)）。
- ⇔ の後は 220ms 後に描き直すので、テストはそれ以上待ってから測る。幅が変わると `.hlx-hint` の折り返し行数が変わり、グラフより下の位置は変わりうる（REQ 8章(5)。本件の対象外）。比較は「同じ幅での切り替えの前後」で行う。

### 3.3 行数が4未満のとき（F-06 の決定）
- 決定：**行数ぶん縮む（現行の規則のまま）。** H = 25 + 41 × 行数。
- 理由：行数を4に固定して空の行を描くと、表示に情報の無い帯ができ、案2 と同じ不自然さが出る。行数は表示の切り替えでは変わらないので、縮んでも切り替えの前後の高さは同じ。
- 現行の `analyzer.js` は `count`・`accel`・`same`・`score` の4つの配列を必ず返す（190〜197行。確認）。キャッシュはチャット（items）だけで、結果は毎回計算し直す。したがって通常の使い方では4行になる。4未満は、将来 analyzer が配列を返さなくなった場合の守りとして扱う。

### 3.4 描画の負荷
- ヒートマップの塗りは、画面の横 1px ごとに `fillRect(x, y, 1, rh)` を1回呼ぶ（363行）。呼ぶ回数は変わらず、1回の塗る高さが 18px→38px になるだけ。マウスを動かすたびに `drawChart()` が呼ばれる（`onChartHover`）が、折れ線（現行 38px）と同程度の負荷になる見込み。
- `canvas.width`・`canvas.height` の再設定（335行）は毎回行われる（現行どおり）。高さが変わらなくなるので、切り替えのときにパネルの配置の計算（レイアウト）がやり直されることも減る見込み。

### 3.5 panel.css を変えない理由
- canvas の高さは content.js が `canvas.style.height` で毎回決めている。`.hlx-chart` は `width: 100%; display: block;` だけで高さの指定が無い（102行。確認）。CSS で高さを固定すると content.js の値と二重になり、行数の変化（3.3 節）に追従できないので、CSS は変えない。

### 7.2 テストの観点（詳細は DD・TS で決める）
新規 E2E（模擬YouTube、解析が `done` になるまでは既存と同じ手順）：
1. **位置の比較（A-01〜A-04）**：切り替え前に「スコア順」「時系列順」ボタン、最初の `.hlx-row`、canvas の `getBoundingClientRect()` の top・height を記録 → 「折れ線」を押す → 再取得して差が 1px 以内 → 「ヒートマップ」を押す → 同様。5往復して毎回、最初の値と比べる。比較の前にパネルの `scrollTop` が同じであることを確かめる（または 0 にそろえる）。canvas の高さが 189 ± 1 であることも確かめる（4行の場合）。
2. **幅と範囲（A-05・A-06）**：⇔ を押して 220ms より長く待ってから 1 を繰り返す。ビューポート幅 1400・800・500（高さは 1000 のまま）で 1 を繰り返す。500px ではパネルが `max-width: 100vw` で縮むので、その状態でも成り立つこと。表示範囲 select を「再生位置の前後15分」「前半」「後半」にして 1 を繰り返す。組み合わせの数（全通りか代表か）は TS で決める。実行時間が長くなりすぎる場合は、ブラウザの起動を1回にしてビューポートを `set_viewport_size` で変える。
3. **描画の中身（A-07・A-09）**：両表示で、▼の位置（canvas の上端 0〜MARK_H の帯）にインクがある、目盛り（下端の AXIS_H の帯）にインクがある、4行のラベルの位置（x < LABEL_W、各行の縦の中央付近）にインクがある、再生位置の線とシークバーの点線が `GAP_INK_JS`（38 に直した版）で見つかる。`hlx-on` が押した方のボタンに付いている。
4. **クリック（A-08）**：折れ線にしてから、既存 `test_panel_analysis_and_video_sync` と同じ「グラフ中央のクリック → 30秒前へ」の確認。ffmpeg が無いときは既存と同じく省略。
5. **並べ替え（A-10）**：切り替えた後に「時系列順」→ 先頭の行の時刻が最小になる、「スコア順」→ 元の先頭に戻る。
6. **画像（4.2 節）**：ヒートマップ・折れ線 × 通常幅・広げた幅の4枚を `ARTIFACTS` に保存（社長確認用。合否の判定には使わない）。
- 修正前のコードで 1 を実行すると差が 80px になって失敗することを、テストの有効性の確認として一度見ておくのが望ましい（REQ 5章の注記）。

既存テスト（A-11）：単体・E2E（4件）・共通指標仕様の適合がすべて通ること。手動（A-12）：運用係が実配信で確認。A-13：`git diff extension/manifest.json` が空。

### 7.3 注意（実装で壊しやすい点）
- **N-1 `GAP_INK_JS` の行の高さ**：既存 E2E の `GAP_INK_JS`（113行）は `const rh = heat ? 18 : 38` と、表示ごとの行の高さを持っている。変更後もこのままだと、ヒートマップのときに「行のすき間」ではなく「行の中（塗られた所）」を読み、ほぼ全幅にインクが見つかって `near()` が**中身を確かめずに通ってしまう**（失敗はしないが確認にならない）。38 に統一すること。既存の `test_panel_analysis_and_video_sync` はヒートマップの状態で `GAP_INK_JS` を使っているので、この修正は既存テストの意味を保つために必須。
- **N-2 クリック位置**：既存テストはグラフの上端から 30px の所をクリックする（225行）。変更後はヒートマップでも1行目の中（9〜47px）に当たり、問題ない見込み。
- **N-3 E2E のセレクタ**：新しい部品は足さない。テストで切り替えボタンを押すときは、`.hlx-chip-btn` が並べ替えボタンと共通のクラスなので、文字（「折れ線」「ヒートマップ」）で特定する（`.hlx-tl-ctl` の中に絞るなど）。`.hlx-primary` は既存どおり解析ボタン。
- **N-4 折れ線の画素を変えない**：折れ線の描き方の式（371行）に手を入れない。定数の追加と `rh` の決め方だけを変える。
- **N-5 ⇔ の待ち**：⇔ の後は `setTimeout(drawChart, 220)`。panel.css の transition は開閉の `transform`（44行）・進み具合の棒・案内の `opacity` だけで、パネル幅には付いていない（確認）。したがって 220ms より長く待てば、幅と描画の両方が確定している見込み。
- **N-6 スクロール位置**：パネルは `overflow-y: auto`。テストの途中でスクロールすると top の比較が狂うので、比較の前後で `scrollTop` を記録し、同じであることを確かめる。
