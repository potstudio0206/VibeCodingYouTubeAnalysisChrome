## 2. 実配信での動作確認（スモークテスト）
YouTube の配信アーカイブには、同じ動画に複数のURL形式があります（2.1）。拡張機能は URL の形で動画かどうかを判定するため、**1本の動画につき /live/<ID> 形式と /watch?v=<ID> 形式の両方**で確かめます（INC-0001：/live/ 形式だけボタンが出なかった）。

### 2.1 URL形式と対応状況
次の表は、コード（extension/manifest.json の matches、extension/viewmodel/videoid.js）を読んで確かめた内容です（2026-10-30、版数 1.2.0 の作業ツリー）。

| URL形式 | 例 | ボタン・解析 | 根拠 |
|---|---|---|---|
| /watch?v=ID | https://www.youtube.com/watch?v=fPnkoOtQIyE | 対応 | videoid.js が pathname `/watch` の `v=` を読む |
| /live/ID | https://www.youtube.com/live/fPnkoOtQIyE | 対応 | videoid.js が `/live/ID`（末尾の `/` は可）を読む。`?si=` などの付き物は読まない |
| /shorts/ID | https://www.youtube.com/shorts/xxxxxxxxxxx | 対象外（ボタンは出ない） | videoid.js は null を返し、content.js の onNav がボタンを隠す。部長決定（QA-0001） |
| /embed/ID | https://www.youtube.com/embed/xxxxxxxxxxx | 対象外（ボタンは出ない） | 同上。manifest の matches は `https://www.youtube.com/*` のみで、all_frames の指定はない |

- 動画ID は英数字・`-`・`_` だけを受け付けます（videoid.js）。それ以外の文字を含むと、ボタンは出ません。
- manifest の matches が `https://www.youtube.com/*` なので、`www.youtube.com` 以外のドメイン（m.youtube.com など）で動くかどうかは、確かめていません（未確認）。確認用URLにも使わないでください。
- YouTube が将来、URL形式を増やしたり変えたりしたら、videoid.js と本表の更新が必要です（動向調査係から共有を受けたら、課長へ報告）。

### 2.2 手順
1. ops/smoke-urls.txt から、前回の次のURLを選ぶ。
2. 選んだURLから動画ID（`/live/` の後ろ、`?` の前の11文字）を取り、次の2つのURLを作る。`?si=` 以降は付けなくてよい。
   - /live/ 形式：`https://www.youtube.com/live/<ID>`
   - /watch 形式：`https://www.youtube.com/watch?v=<ID>`
   - 例（1本目）：`https://www.youtube.com/live/fPnkoOtQIyE` と `https://www.youtube.com/watch?v=fPnkoOtQIyE`
3. Claude in Chrome が使えるセッション（`claude --chrome`）で、まず /live/ 形式を開く。右下に「見どころ」ボタンが出るのを確かめ、押して「このアーカイブを解析」を押す。
4. 確かめる：完了の表示（コメント数・候補の数）、グラフのクリックで動画がジャンプする、再生位置の赤い線が動く。
5. 同じ動画を /watch 形式で開き、3〜4 を繰り返す。2つの形式で、コメント数と候補の数が同じ程度か見比べる（INC-0001 では /watch 形式でコメント574件・候補20か所。同じ動画でも、取得のたびに数が少し違うかもしれないが、桁が違うときは不具合として扱う）。
6. どちらかでボタンが出ない・解析が始まらないときは、4章の最初の行に従う。
7. Claude in Chrome が使えないときは、E2Eテスト（`python -m unittest discover -s tests/e2e -v`）だけ実行し、「実配信は未確認」と記録する。
8. docs/07_ops/logs/YYYY-MM-DD.md に記録する。**どの動画IDを、どちらの形式で確かめたか**を、形式ごとに書く（例：「/live/ 形式：合格」「/watch 形式：合格」）。片方だけ確認したときは、その旨を書く。

### 2.3 INC-0001 の再確認（修正のマージ後に1回）
INC-0001 の修正（ブランチ fix/live-url-support）は、自動テストでは合格していますが（QA-0001）、**本物の /live/ URL での確認はまだ行っていません**。修正のマージと拡張機能の読み込み直し（3章）のあと、次を行います。
1. ops/smoke-urls.txt の /live/ 形式のURLを開き、2.2 の 3〜4 を行う（INC-0001 で症状が出た fPnkoOtQIyE を最初に使う）。
2. 同じ動画を /watch 形式でも確かめる（2.2 の 5）。
3. docs/07_ops/logs/ の運用記録に結果を書き、保守運用課長へ報告する。INC-0001 を閉じるのは保守運用課長です。

## 3. 拡張機能の更新（社長のChromeへの反映）
入れ方は2通りあります（extension/README.txt の「更新するとき」と同じ手順）。どちらで入れたかは、読み込み済みの「extension」フォルダの親に `.git` フォルダがあるかで分かります（ある：git clone、ない：ZIP）。

**(a) git clone で入れた場合**
1. リポジトリのフォルダで `git pull` を実行する（main を最新にする。作業ブランチを確かめたいときは、そのブランチに切り替えてから行う）。
2. Chrome の `chrome://extensions` で「配信 盛り上がり検知 in Chrome」の更新ボタン（↻）を押す。
3. YouTube のタブを再読み込みする。

**(b) ZIP で入れた場合**
1. 新しい ZIP をダウンロードして解凍する。
2. 読み込み済みの「extension」フォルダの中身を、新しい「extension」フォルダの中身で上書きする。別の場所に解凍して読み込み直さず、**同じ場所に上書きする**。
3. `chrome://extensions` で更新ボタン（↻）を押す。
4. YouTube のタブを再読み込みする。

どちらも、↻ と YouTube タブの再読み込みの**両方**が必要です。

**manifest.json の content_scripts にファイルを追加・変更・並べ替えたときは、必ず ↻ と YouTube タブの再読み込みの両方を行います。** 拡張機能の再読み込み（↻）だけでは、すでに開いている YouTube のタブには新しい構成が入りません。タブの再読み込みを忘れると、古いコードのまま（または新旧が混ざった状態）で動きます。
- 今回（REQ-0001／DD-0001、コミット 6f7deac）は、manifest.json に変更がありません。確かめた内容：content_scripts は `analyzer.js`、`fetcher.js`、`viewmodel/videoid.js`、`content.js` の順のまま、permissions は `storage`・`unlimitedStorage` のまま、版数は 1.2.0 のままです。初回案内とエラー表示の関数は videoid.js に追加されました（新しいファイルは増えていません）。
- 直近の例：INC-0001 の修正で、content_scripts.js に `viewmodel/videoid.js` が加わりました（`analyzer.js`、`fetcher.js`、`viewmodel/videoid.js`、`content.js` の順）。content.js が videoid.js の関数を使うため、**videoid.js は content.js より前**に書く必要があります。順番を変えたときも、同じ再読み込みを行います。
- 反映を確かめるには、YouTube のタブを再読み込みしたあと、/live/ 形式のURLを開いて「見どころ」ボタンが出ることを見ます（2.2 の 3）。

## 4. よくある障害と対応
| 症状・文言 | 原因 | 対応 |
|---|---|---|
| 「見どころ」ボタンが出ない | 1) URL形式が対象外（/shorts/・/embed/、ほか）。2) 古い拡張機能のまま（読み込み直しの後に YouTube のタブを再読み込みしていない）。3) ページの読み込み途中 | **まずアドレスバーのURL形式を確認する**（下の切り分け）。次に YouTube のタブを再読み込みする |
| 「YouTubeからの取得に失敗しました（エラー 番号）。何度か試しても同じ場合は、YouTube 側の仕様変更で読み取れなくなっている可能性があります。」 | YouTube の内部APIの変化、一時的な制限 | 時間をおいて「再取得」。続くなら 4.2 に従って報告（動向調査係にも共有） |
| 「YouTubeからの応答がありません。少し時間をおいて再試行してください。」＋仕様変更の可能性の一文 | 取得を繰り返しても応答が得られなかった（429・5xx の再試行を使い切った） | 時間をおいて「再取得」。ネットワークも確かめる。続くなら 4.2 |
| 「ページ情報を読み取れませんでした。ページを再読み込みしてからもう一度お試しください。」＋仕様変更の可能性の一文 | ページの読み込み途中、または YouTube のページ構造の変化 | YouTube のタブを再読み込みして再実行。続くなら 4.2 |
| 「チャットリプレイの読み込み口が見つかりませんでした。」＋仕様変更の可能性の一文 | YouTube の内部の仕組みの変化の疑い | 別の動画でも出るか確認し、4.2 |
| 「この動画にはチャットリプレイがありません（通常の動画、チャット無効、またはアーカイブ処理中）。」（どれにも当たらないのに出る場合は仕様変更の可能性、の一文が付く） | 通常の動画・チャット無効・処理中。どれでもないときは YouTube 側の変化の疑い | まず別の動画（ops/smoke-urls.txt）で確認。確認用の動画でも出れば 4.2 |
| 「この動画は未ログインでは見られないため解析できません（メンバー限定・年齢制限など）。」 | メンバー限定・年齢制限 | 対象外（仕様変更の可能性の一文は付かない） |
| 「配信中は解析できません。配信が終わってアーカイブになってから実行してください。」 | ライブ中 | アーカイブになってから（仕様変更の可能性の一文は付かない） |
| 「コメントが1件も見つかりませんでした。」 | 取得は成功したが、コメントが0件（エラーではなく状態表示） | 別の動画で確認。確認用の動画でも出れば 4.2 |
| 「解析中に予期しないエラーが起きました。ページを再読み込みしてから、もう一度お試しください。」（＋仕様変更の可能性の一文） | 想定していなかった例外。画面には詳細が出ない | 開発者ツールのコンソール（F12）で `[盛り上がり検知]` から始まる行を探し、その内容を写して 4.2 に従って報告 |
| 「見どころ」ボタンは出るが、パネルの上に「はじめにお読みください」が出続ける | 初回案内の確認記録が保存されていない（4.3） | 4.3 に従う |

「仕様変更の可能性」の一文は、「何度か試しても同じ場合は、YouTube 側の仕様変更で読み取れなくなっている可能性があります。」です（コード：fetcher.js の HLX_SPEC_CHANGE_NOTE）。この一文が付くエラーが、**確認用の動画（ops/smoke-urls.txt）の全部で、時間をおいても出る**ときは、YouTube 側の変化として扱います（4.2）。

### 4.1 「見どころ」ボタンが出ないときの切り分け
ボタンが出ない場合、エラーの文言もコンソールの出力も出ません（拡張機能は「動画ではない」と判断して、ボタンを隠しているだけです。INC-0001）。次の順に確かめます。
1. **URL形式を確認する。** アドレスバーが `https://www.youtube.com/watch?v=<ID>` または `https://www.youtube.com/live/<ID>` か。
   - /shorts/ や /embed/ の場合は、対象外なので不具合ではない。/watch または /live/ の形式で開き直す。
   - `www.youtube.com` 以外のドメインの場合は、対象かどうか未確認（2.1）。`www.youtube.com` で開き直す。
   - /live/ と /watch のどちらでもよい。同じ動画を、もう一方の形式で開いてボタンが出るか見る（出るなら、URL形式に関する不具合の疑い。課長へ「論点」に書いて報告）。
2. URL形式が対象なのにボタンがない：YouTube のタブを再読み込みする。
3. まだ出ない：`chrome://extensions` で拡張機能の更新ボタン（↻）を押し、YouTube のタブを再読み込みする（3章）。拡張機能が「オン」になっているかも見る。
4. それでも出ない：不具合として、URL、版数（`chrome://extensions` に表示）、再現手順を添えて保守運用課長へ報告する。

### 4.2 YouTube 側の仕様変更が疑われるときの報告
1. 症状が出た動画のURL、パネルに出た文言（そのまま）、版数（`chrome://extensions` に表示）、時刻を控える。
2. ops/smoke-urls.txt の別の動画でも同じか確かめる（2.2）。**全部で出る**なら仕様変更の疑いが強い。
3. 保守運用課長へ「論点」に上の内容を書いて報告する。動向調査係（研究課）への共有は、部長が回す。修正の要否は課長・部長が判断する（運用係は直さない）。
4. 利用者向けの案内は README.txt の「うまくいかないとき」にあります（直らないときは GitHub の Issue で知らせる、という案内）。GitHub の Issue の運用（誰が見るか）は、今回の変更では決まっていません（未決）。

### 4.3 初回案内（「はじめにお読みください」）の運用
コードで確かめた動作（extension/content.js、extension/viewmodel/videoid.js）：
- 案内はパネルの上部に出ます。「見どころ」ボタンを押してパネルを開くと見えます。
- 「確認しました」を押すと、キー `hlxNoticeAck` に数値 1（版 1）を `chrome.storage.local` へ保存し、以後は出ません。開いている他の YouTube タブでも、保存の変更を受けて案内が消えます。
- 保存された値が数値で 1 以上のときだけ「出さない」と判断します。それ以外（保存がない、文字列、0 など）は出します。将来、案内の文言を変えて版を上げると（HLX_NOTICE_VERSION）、全員にもう一度出ます。
- 読み出しが終わるまでは案内を隠しているため、パネルを開いた瞬間は出ていないことがあります。

| 症状 | 考えられる原因 | 確かめ方・対応 |
|---|---|---|
| 初回なのに案内が出ない | 1) すでに確認済み。2) 古い拡張機能のまま（YouTube のタブを再読み込みしていない） | YouTube のタブの開発者ツール（F12）のコンソールで、保存の中身を見る（コンテンツスクリプトの実行環境を選ぶ必要があるため、見づらいときは課長へ相談）。1 なら確認済みで正常。なければ ↻ とタブの再読み込み（3章） |
| 何度も出る | 1) 保存データを消した（下の4.4）。2) シークレットウィンドウや別のChromeプロファイルで開いている（保存が別）。3) 保存に失敗している（拡張機能の再読み込み直後など） | 「確認しました」を押したあとYouTubeのタブを再読み込みして、なお出るなら、版数・Chromeのバージョン・手順を添えて保守運用課長へ報告。保存に失敗したときは、そのページでは隠れたままで、次に読み込んだときにまた出る（コードの仕様） |
| 保存データを消したあとに、また出た | 正常。`hlxNoticeAck` が消えたため | 「確認しました」を押し直す |

### 4.4 保存データ
コードで確かめた保存先とキー（extension/content.js、extension/options.js）：

| キー | 内容 | 保存先 | 「保存したチャットをすべて削除」で |
|---|---|---|---|
| `chat_<動画ID>` | 解析した配信の情報とチャット | `chrome.storage.local` | 消える |
| `seen_<動画ID>` | 「確認済み」にした見どころの印 | `chrome.storage.local` | 消える |
| `hlxNoticeAck` | 初回案内を確認した記録（版 1） | `chrome.storage.local` | **消えない** |
| `hlxSettings` | 設定 | `chrome.storage.sync`（Chrome の同期が有効だと Google アカウントを通じて同期されることがある） | **消えない**（設定画面の「初期設定に戻す」で消える） |

- 削除ボタンが消すのは、キーが `chat_` または `seen_` で始まるものだけです（options.js の clearCache）。
- `hlxNoticeAck` を消すには、拡張機能を削除して入れ直す（保存領域も消える）か、開発者ツールで保存領域を操作します。通常の運用で消す必要はありません。
- 拡張機能そのものの削除は、Chrome の拡張機能の管理画面（chrome://extensions）から行えます（保存領域の扱いは未確認）。
- 保存内容の詳しい説明は、設定画面（⚙）の「保存したチャット」と README.txt の「保存するデータ」にあります。コメントを書いた人の名前などは保存しません。送信先は YouTube だけです。

## 6. 確認用URLの管理
- ops/smoke-urls.txt に、チャットリプレイのある公開アーカイブを3〜5本。社長が登録する。
- 現状の5本は、すべて /live/<ID> 形式です。**/watch 形式のURLを別に登録する必要はありません。** 運用係が2.2 の 2 でIDから /watch 形式を作って確かめます（登録しているのは動画で、URLの形式ではないため）。
- 新しく登録するときは、/live/ 形式でも /watch?v= 形式でもよい。どちらで登録されても、2.2 に従って両方の形式で確かめる。
- 登録できないもの：メンバー限定・年齢制限・配信中・チャットリプレイのないもの。/shorts/ と /embed/ の形式（対象外）。
