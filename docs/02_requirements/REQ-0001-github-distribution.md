# REQ-0001 GitHub 配布の体裁整備

## 0. 読み方（確かめた範囲）
- 「確認」は、2026-10-30 に本リポジトリのコードと文書を読んだこと。YouTube への実リクエスト、拡張機能の実機操作、通信の実測はしていない。
- 「未確認」と書いたものは事実ではない。実装前に確かめる点として 8章にも並べた。
- 本書は法的助言ではない。

## 1. 背景と目的
### 1.1 背景
- 社長は判断待ち #5 で、Chrome ウェブストアへの公開を保留し（A1）、当面は GitHub からクローン（または ZIP ダウンロード）して使う「自己責任の拡張機能」として配布する体裁にすると決めた。あわせて、画面での開示、説明書の整理を要件定義課に回すとした（F）。
- RS-0001 は、ストアの有無にかかわらず次が不足と整理している。
  - 利用者向けの「何を読み、何を保存するか」の開示が画面に無い（C-7）。
  - エラー表示に「YouTube 側の仕様変更の可能性」が無い（4(f)）。ただし README.txt の「うまくいかないとき」には既にある。
  - README.txt が配布の実態と合っているか（4(g)）。
- 現状の確認（コードと文書）：
  - `extension/README.txt` の導入手順は「この zip を解凍する。できた『hlx-ext』フォルダ」「『hlx-ext』フォルダを選ぶ」と書く（7・11行）。リポジトリに `hlx-ext` というフォルダは無い（`git ls-files` と grep で確認。"hlx-ext" は README.txt の中にしか現れない）。GitHub から入れる場合に選ぶのは `extension` フォルダで、実態と食い違っている。
  - リポジトリ直下の `README.md` の「使う」は、`extension` フォルダを読み込むとだけ書き、自己責任・保存データ・無保証の記述は無い。
  - リポジトリは公開（`gh repo view`：visibility = PUBLIC）。ライセンスファイルは無い（`LICENSE*`・`COPYING*` が無い。`gh repo view` の licenseInfo = null）。

### 1.2 目的
- GitHub から入れて使う利用者が、(1) 迷わず導入・更新でき、(2) 非公式で自己責任のツールだと分かり、(3) 何がこのPCに保存されるかを知ったうえで使え、(4) 壊れたときにYouTube側の変更の可能性に気づける状態にする。
- 製品の機能（解析・グラフ・見どころ）は変えない。

### 1.3 範囲外
- B1（ストア公開時は掲載名から「in Chrome」を外す）、C1（プライバシーポリシーは GitHub Pages、連絡先は Issue のみ）：ストア公開時の決定。今回は実施しない（付録Bに申し送りだけ書く）。
- D（開発者登録）、E（`unlimitedStorage` の見直し）、G（ストア用スクリーンショット）：保留・見送り。要件にしない。
- 権限の追加・変更、通信先の追加、取得方式の変更、保存する項目の追加（初回案内の既読記録を除く。F-24）。
- YouTube 利用規約との関係の判断（RS-0001 C-16・C-17）。本件は「規約に適合する」と主張する書類ではない。

## 2. 利用場面（切り抜き師がどう使うか）
1. 切り抜き師が GitHub のリポジトリページを開く。README.md の冒頭で、これが非公式・自己責任の拡張機能だと分かり、入れ方と詳細（`extension/README.txt`）への道が見える。
2. `git clone` か「Code → Download ZIP」で入手し、`chrome://extensions` のデベロッパーモードで `extension` フォルダを読み込む。
3. YouTube の配信アーカイブを開き、パネルを開く。初回だけ、「非公式・自己責任」「何を読み、何をこのPCに保存するか」の案内が出る。読んで閉じると、通常の画面になる。以後は設定画面（⚙）でいつでも同じ内容を読め、保存したチャットを削除できる。
4. 数週間後に YouTube 側が変わって解析が失敗したとき、エラー文から「YouTube 側の仕様変更の可能性」に気づき、リポジトリの Issue で知らせるか、更新を待つ。
5. 更新があれば、`git pull`（または ZIP の入れ替え）→ ↻ → YouTube タブ再読み込みで入れ替える。

優先度は 必須／推奨。「実施主体の案」は目安で、確定は設計課。

### 3.3 画面での開示（何を読み、何を保存するか）
推奨案（詳細の見せ方は設計課に委ねる）：**初回のみの案内＋設定画面への常設**。解析の邪魔にならないよう、案内は閉じられ、解析ボタンを塞がない。

| No | 要件 | 優先度 |
|---|---|---|
| F-20 | 初回案内：拡張機能を入れて初めてパネルを開いたとき、パネル内に短い案内を表示する。内容は F-10 の要約（非公式・自己責任・動かなくなることがある）と、F-22 の要約（何を保存するか）、詳細は設定画面（⚙）にあること。利用者が「閉じる（または確認した）」操作をするまで表示し、操作後は二度と自動では出さない | 必須 |
| F-21 | 設定画面（options.html）に、F-10 と F-22 の全文を常設する。保存したチャットの削除ボタンの近く（「保存したチャット」の項）に置き、削除の説明と同じ場所で読めるようにする。いつでも読み返せる | 必須 |
| F-22 | 保存データの開示は、実際のコードの動作と一致させる。次の事実を含める（付録A に案文）。(1) 読み取るもの：動画ページの情報（動画ID、タイトル、配信者名、長さ、「よく再生された部分」のデータ）と、チャットのコメント本文・時刻・種別（通常／有料／メンバー系）。(2) 保存するもの：解析した動画ごとに、動画の情報（動画ID、タイトル、配信者名、長さ、「よく再生された部分」のデータ。`info`）、チャットの時刻・種別・本文（`items`。メンバー系は本文を保存せず、種別と時刻のみ）、保存した日時（`at`。content.js 169行で `Date.now()` の値、つまり保存した時刻）を保存する。見どころを「確認済み」にした印（その見どころの開始秒）。設定（候補の出やすさ、集計の細かさ、候補の最大数、何秒前から再生するか、検知するワード）。(3) 保存場所：このPCの Chrome 内（拡張機能用の保存領域）。設定は Chrome の同期機能を有効にしていると Google アカウント経由で同期されうる。(4) コメントを書いた人（視聴者）の名前・チャンネルID・アイコン・金額は保存しない（配信者名は動画の情報として保存する。矛盾しない書き方にする）。ただし、視聴者が自分でコメント本文に書いた内容は、そのまま保存される。(5) 外部送信：この拡張機能の作者や第三者のサーバーへは送らない。通信するのは YouTube（動画ページとチャット取得）だけ。(6) 削除方法 | 必須 |

| F-24 | 初回案内の「確認済み」の記録は、`chrome.storage.local` に 1 キー追加してよい（名称・形式は設計課。`chat_` や `seen_` で始めない）。このキーは F-22 の保存データの開示に含める。設定画面の「保存したチャットをすべて削除」で消えてもよいか、消えない扱いにするかは設計課が決め、決めた方を開示と一致させる（推奨：削除ボタンでは消さない。理由：消すと案内が毎回再表示され邪魔になるため。ただし完全に消したい人のために、拡張機能の削除で消える旨を F-22(6) に書く）。権限（permissions）は追加しない | 必須 |
| F-25 | 削除の導線を開示と一致させる。現状、設定画面の「保存したチャットをすべて削除」は `chat_` と `seen_` で始まるキーだけを `chrome.storage.local` から消す（options.js 57〜63行）。設定（`hlxSettings`、`chrome.storage.sync`）は別の「初期設定に戻す」で消える（options.js 44〜48行）。開示では、この2つの操作がそれぞれ何を消すかを区別して書く。「すべて削除」の文言が設定まで消すと誤解されない書き方にする（ボタンの文言そのものの変更は不要。変えるなら設計課が決める） | 必須 |

| F-27 | 初回案内は、動画ページ以外では出さない（パネルは動画ページのみで開く現状を維持）。案内の表示・非表示は、解析の開始、結果の表示、再生位置との連動、見どころの印の描画に影響しない | 必須 |

### 3.4 エラー表示への「YouTube 側の仕様変更の可能性」の追記
現行のエラー文は、取得処理（extension/fetcher.js）が投げるものを、パネルの状態表示（content.js 176〜180行：`setStatus(e.message || String(e))`）がそのまま出している。追記の対象は、取得や読み取りの失敗系で、原因が YouTube 側の仕様変更でも起こりうるもの。原因が利用者に明らかなものには足さない。

| fetcher.js 141行 | この動画は未ログインでは見られないため解析できません（メンバー限定・年齢制限など）。 | 視聴制限 | 対象外 | 原因が明らか |

| content.js 189行 | 中止しました。 | 利用者の操作 | 対象外 | 失敗ではない |

### A.2 保存データの開示（設定画面、README.txt、初回案内の要約）
> **このツールが読むもの**：開いている動画の情報（動画ID・タイトル・配信者名・長さ・「よく再生された部分」のデータ）と、チャットのコメント（本文・投稿時刻・通常／スーパーチャット／メンバー系の種別）。
> **このPCに保存するもの**：
> ・解析した配信の情報（動画ID・タイトル・配信者名・長さ・「よく再生された部分」のデータ）と、保存した日時。
> ・解析した配信ごとのチャット（コメントの本文・時刻・種別）。メンバー系は本文を保存しません。
> ・「確認済み」にした見どころの印。
> ・設定（候補の出やすさ、集計の細かさ、候補の最大数、何秒前から再生するか、検知するワード）。
> ・この案内を確認したという記録。
> **保存場所**：このPCの Chrome の中（拡張機能用の保存領域）。設定は、Chrome の同期を有効にしている場合、Google アカウントを通じて同期されることがあります。
> **保存しないもの**：コメントを書いた人（視聴者）の名前・チャンネル・アイコン・スーパーチャットの金額。（配信者名は、配信の情報として保存します。）ただし、コメント本文に視聴者が自分で書いた内容は、そのまま保存されます。
> **送信**：この拡張機能の作者や第三者のサーバーへ、データを送ることはありません。通信するのは YouTube だけです（動画ページとチャットを読み込むため。ログイン情報は付けません）。
> **削除**：「保存したチャット」の「保存したチャットをすべて削除」で、解析したチャットと「確認済み」の印が消えます（設定は消えません。設定は「初期設定に戻す」で消えます）。拡張機能そのものは、Chrome の拡張機能の管理画面（chrome://extensions）から削除できます。

注：「ログイン情報は付けません」は fetcher.js の `credentials: 'omit'`（3か所とも）に基づく。「送信しない」は `fetch` が 3 か所とも `location.origin`（youtube.com）宛てであることに基づく（RS-0001 1.5 と本調査の grep）。実測は未実施（8章(5)）。「拡張機能の削除でデータが消えるか」は未確認のため、案文に含めていない（F-26）。
